# Roadmap

The immediate objective is **stable, restartable, installable**. Work proceeds in
this order; new visual effects, DeX, second-screen, Remote and multi-agent
capabilities are deferred. Milestones are acceptance criteria, not release dates.

## Available now: source alpha

The source preview opens the Android host, integration and checks to contributors.
Real local desktop work and bounded recovery have been demonstrated on the
development Fold. A fresh-install consumer APK and dependable long sessions are
not yet qualified.

## 1. Dependable sessions

Fix verified lifecycle defects, measure global Android child-process pressure
separately from the app UID count, and retain independent conversations and
stateful tools. Exercise two conversations, ten-minute background intervals,
extended work, real folding, keyboard/focus and repeated start/stop.

**Exit:** the [daily-use matrix](daily-use-qualification.md) passes on a named APK
and device, with real tool results, process observations and unchanged projects.
Host tests and a visible desktop are insufficient.

## 2. Reproducible installation

Build from declared, fingerprinted inputs with a candidate APK and its provenance.
Finish the fresh-root coordinator, shared guest bundle format and required guest
engine/dependencies. Keep official-client acquisition and account sign-in separate.
Exercise interruption, storage exhaustion, retry and signature-preserving updates.

**Exit:** a contributor starts from a clean checkout and supported device, follows
one documented setup and completes a real local Codex task. Record before/after
Knox, bootloader, verified boot, One UI and data-preservation checks. A development
update candidate is explicitly labelled until this succeeds.

## 3. Safe official-client updates

Monitor official Linux ARM64 metadata; authenticate new payloads independently.
Refuse unrecognized client bytes before guest mutations. Qualify adapter recovery,
local tools and the daily-use matrix before activation. Treat host, engine, Linux
environment and proprietary desktop client as separate transitions.

**Exit:** the update matrix records supported transitions, preserved projects and
recoverable failures. The fresh-install transaction is not reused as an updater.

## Later: wider experience

Remote, DeX, additional screens/devices and advanced integrations resume once the
first three gates pass. Each advertised capability needs a repeatable real test.
Focused fixes, reproducible build inputs and redacted lifecycle traces are the
most useful contributions now.
